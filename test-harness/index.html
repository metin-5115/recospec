Recospec Locator Test Harness

Eight interlinked pages that exercise every locator strategy and combination. Record across them with the extension, or run the automated oracle: pnpm test test-harness.

How this works

Every testable element is annotated with what the engine is expected to produce. The companion spec (harness.test.ts) reads these annotations, runs the real locator engine against each element, and asserts the result.

  • data-expect="testid" — the engine's primary strategy must equal this.
  • data-expect-min="80" — primary score must be ≥ this.
  • data-expect-self — the primary must resolve to exactly this element.
  • data-expect-pw="getByTestId|filter" — the Playwright expression must contain each |-separated substring.
  • data-expect-absent="76.800" — the value(s) must appear in no part of the generated locator (dynamic-value leakage guard).
  • data-promote="button" — a leaf click here must be promoted to an ancestor of this tag before any locator is built.

Page map

Each page focuses on one part of the decision pipeline.

  • 01 — Attributes: full test-id family + name / placeholder / alt / title.
  • 02 — ARIA & Roles: aria-label, aria-labelledby, role + accessible name.
  • 03 — Forms: label[for], wrapped labels, sensitive fields (env-var params).
  • 04 — Text / ID / CSS: visible text, stable id, stable-class CSS, nth-of-type.
  • 05 — Click Promotion: icon/text leaf clicks promoted to button / anchor / card.
  • 06 — Card Lists: repeated rows → container anchor keyed by a stable label.
  • 07 — Dynamic & Fallback: dynamic class/id rejection, relative-scoped XPath last resort.
