03 — Forms & labels

label[for], wrapped labels, select / textarea. A label is a control's accessible name, so the engine emits the idiomatic getByRole(…, { name }) (role-name), not a raw id.

Explicit label[for] → role-name / label

A stable id is present, but the label-derived accessible name wins. The password field has no ARIA role, so it resolves via the label instead.

Wrapped label → role-name

Input nested inside its label, no for attribute.

Select & textarea → role-name

Non-input controls still resolve through their accessible name.
