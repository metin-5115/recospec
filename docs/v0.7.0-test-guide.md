---

## 1. PlayForge ne yapar?

PlayForge bir **kayıt-tabanlı test otomasyon araç zinciri**'dir. Üç yüzeyden
oluşur, hepsi aynı IR (Intermediate Representation) pipeline'ını paylaşır:

| Yüzey                 | Ne yapar                                                                                       | Build çıktısı                            |
| --------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------- |
| **Chrome Extension**  | Tarayıcıdaki etkileşimleri kaydeder, akıllı locator seçer, Page Object Model üretir.           | `dist/` (MV3 unpacked)                   |
| **CLI (`playforge`)** | Mevcut bir test projesine kayıt JSON'unu uygular — page object + scenario + Claude prompt.     | `dist/cli/index.js` (~183 KB ESM)        |
| **VS Code Extension** | Yukarıdaki iki yüzeyi tek IDE içinde orkestre eder: Record → Apply → Claude prompt round-trip. | `releases/playforge-0.7.0.vsix` (585 KB) |

**Hedef**: Manuel düzenleme gerektirmeden çalışan test kodu. Self-healing
fallback'ler, sensitive value redaction, Page Object inference, network
mock'ları — hepsi otomatik.

## 3. Yetenekler — kapsamlı katalog

### 3.1. Locator Engine (9 strateji)

Öncelik sırası:

1. `data-testid` / `data-test` / `data-cy` / `data-qa`
2. Diğer `data-*` test attribute'ları
3. `aria-label`
4. `role + accessible-name`
5. `<label>` ilişkisi
6. Görünür text
7. `id` (whitelist'le güvenli olanlar)
8. CSS selector (stable seed'lere göre)
9. XPath fallback

**Akıllı reddetmeler**: Dinamik class'lar (`css-1a2b3c`, `MuiButton-root-273`)
otomatik reddedilir. ID whitelist statik isim pattern'lerini gözetir.

**Scoring formülü**: `uniqueness*0.4 + semanticStrength*0.3 + stability*0.2 + depth*0.1`

**Test sayısı**: `pnpm test` içinde locator-engine için 80+ unit test.

### 3.2. Self-Healing Locator Chain

Her element ham locator + sıralanmış fallback listesi (`IRFallback[]`) ile
gelir. Üretilen page object'te:

```typescript
// Fallbacks: [aria-label=Sign in] > [role=button name=Login] > [text=Login]
this.loginButton = this.page.getByTestId('login-btn')
```

Scaffold'a `utils/locator.ts` (Playwright `selfHealingLocator`) veya
`cypress/support/locator.js` (`cy.selfHealing`) helper'ı eklenir — runtime'da
primary kırıldığında fallback'leri sırayla dener.

### 3.3. Page Object Inference

Aynı URL'deki step'ler aynı sınıfa gruplanır. Sınıf adı URL path'ten
türetilir (`/login` → `LoginPage`). Her input/click bir field+method'a
dönüşür.

**Method inference v2 — 10 pattern**:

- `search`, `login`, `register`, `submitForm`, `fillForm`, `acceptAndSubmit`,
- `navigateFromMenu`, `selectFromMenu`, `openItem`, `confirmAction`
- Fallback: `click<Name>`, `fill<Name>`, `press<Key>`, `verify<Name>`

Parametre tipleri input type'tan çıkarılır (`number`, `boolean`). Aynı sayfada
method ismi çakışmaları numerik suffix ile çözülür (`login_2`).

Side panel **Method Preview** ile her ismi tek tıkta düzenleyebilirsin —
`methodRenames: Record<"PageClass.oldName", string>` `CODE_GENERATE`
mesajıyla aktarılır.

### 3.4. Network Capture & Mocks

MV3 izin gerektirmeden çalışır — MAIN-world content script
(`network-proxy.ts`, `run_at: document_start`) `window.fetch` ve
`XMLHttpRequest`'i sarmalar. Response body cap: 50 KB.

IR'da `IRActionType: 'network'` step'leri olarak görünür. Opt-in checkbox:
**Include mocks for captured network requests** — açıkken Playwright adapter
`page.route(... route.fulfill(...))` üretir; JSON body live JSON olarak
korunur (`JSON.stringify(...)`), text body string literal'e dönüşür.

### 3.5. Visual Regression

Step listesinde herhangi bir element için "Screenshot match" suggestion
çıkar. Thumbnail + snapshot name input + threshold gösterir. Adapter
çıktıları:

- **Playwright**: `await expect(...).toHaveScreenshot('name.png', { threshold })`
- **Cypress**: `cy.matchImageSnapshot('name', { failureThreshold, failureThresholdType: 'percent' })`

Baseline'lar ilk çalıştırmada üretilir; commit etmek senin işin.

### 3.6. Assertions UI

Point-and-click ile assertion ekleme:

- `visible`, `hidden`
- `text-equals`, `text-contains`
- `value-equals`
- `attribute-equals`
- `count`
- `screenshot` (yukarıda)

Side panel **AssertionBuilder** ile probe mode'a girersin, sayfadaki bir
elemana tıklarsın, suggestion listesi açılır, birini seçersin, kayıt
eklenir.

### 3.7. Sensitive Value Redaction

`sensitive-detector.ts` şu pattern'leri tespit eder:

- Field name regex: `password`, `secret`, `token`, `apiKey`, `pin`, …
- `inputType`: `password`
- `autocomplete`: `current-password`, `new-password`, `one-time-code`, …

Tespit edilenler `TestDataConfig` üzerinden env-var emission'a yönlendirilir.
Adapter idiomatic çıktısı:

| Framework     | Üretim                                                            |
| ------------- | ----------------------------------------------------------------- |
| Playwright TS | `process.env.PLAYFORGE_PASSWORD ?? "change-me"`                   |
| Cypress JS    | `Cypress.env("password") \|\| "change-me"`                        |
| Selenium Py   | `os.environ.get('PLAYFORGE_PASSWORD', 'change-me')`               |
| Selenium Java | `System.getenv().getOrDefault("PLAYFORGE_PASSWORD", "change-me")` |

Scaffold'a fixture/env şablonları eklenir: `.env.example`,
`cypress.env.json.example`, `conftest.py` (`python-dotenv`),
`src/test/resources/test-data.properties.example`.

`logger.ts` redaction guard'ı `password|secret|token|apiKey` key'lerini
console.log çıkmadan önce maskeler.

### 3.8. Session Versioning & Diff Explorer

İlk 3 step'ten sonra `flowSignature` (normalized URL + types + strategies +
selector hash) hesaplanır. Aynı imzaya sahip prior session bulunursa side
panel "Looks like an iteration of <Login Flow>" banner'ı gösterir. Accept
edersen `iterationNumber` bump'lanır, `<family> v<n>` adı verilir.

**SessionDiffModal** — side-by-side iki kolon, 3-pass matcher (actionId →
tight LCS → loose LCS), per-row tone (yeşil added / kırmızı removed / amber
changed), "Export diff as JSON" aksiyonu.

### 3.9. BDD Output (Gherkin)

`--bdd` flag (CLI) veya Output Picker'da "BDD output" checkbox → `.feature`

- step definition dosyaları üretir.

Routing:

- Playwright TS → `features/` + `features/steps/`
- Cypress JS → `cypress/e2e/`
- Selenium Py → `features/`
- Selenium Java → `src/test/resources/features/` + `src/test/java/steps/`

`@cucumber/gherkin` parser'ı mevcut `.feature` dosyalarıyla case-insensitive
title bazlı merge yapar.

### 3.10. 4 Framework Adapter

| Adapter         | Test runner | Page object stili                   |
| --------------- | ----------- | ----------------------------------- |
| `playwright-ts` | Playwright  | TypeScript class, `page.getBy*`     |
| `cypress`       | Cypress     | JS class, `cy.*` commands           |
| `selenium-py`   | Pytest      | Python class, `WebDriverWait`       |
| `selenium-java` | TestNG      | Java class, `@FindBy` + PageFactory |

Hepsi `FrameworkAdapter` SDK'sini implement eder, registry'ye self-register
olur, aynı `IRPage` + `IRScenario` girdisinden idiomatic çıktı üretir.

### 3.11. CLI (`playforge`)

```bash
playforge add <json> [projectDir]    # JSON → page-object + scenario → projeye yaz
playforge init [projectDir]          # .playforgerc.json yaz
playforge prompt <json> [projectDir] # Claude Code prompt'u üret
```

- **Framework auto-detect**: `pom.xml` → selenium-java, `requirements.txt`
  → selenium-py, `package.json` → playwright-ts | cypress.
- **AST-aware mergers**: TS (`@babel/parser`), Py (`spawnSync python -c
'import ast'` + regex fallback), Java (balanced-brace walker),
  `.feature` (`@cucumber/gherkin`). Existing method body'ler asla
  overwrite edilmez.
- **Conflict modes**: `[m] merge`, `[o] overwrite`, `[s] skip`,
  `[r] rename`, `[d] diff`.
- **`--bdd`**: Gherkin output (yukarıda).
- **`--no-redact`** (prompt only): leak guard bypass.

### 3.12. VS Code Extension (v0.7.0 — bu sürümün vitrini)

4 komut:

| Komut                              | İşlevi                                                                              |
| ---------------------------------- | ----------------------------------------------------------------------------------- |
| `PlayForge: Record Flow…`          | Chromium'u PlayForge ext yüklü açar, kayıt → JSON → Output Picker → Apply.          |
| `PlayForge: Apply Existing JSON…`  | Disk'teki JSON'u Output Picker üzerinden uygular.                                   |

**Output Picker webview** — CSP locked (`default-src 'none'`,

- Claude prompt + mode radio (slash / claude-md / prompt)
- Redact sensitive values (default on)
- `Esc` cancel, `Ctrl+Enter` apply.

**Conflict picker** — QuickPick: Merge (canMerge'e göre) / Overwrite /
Skip / Write `.new` / Show diff. Diff `vscode.diff` ile mevcut ↔ untitled
incoming buffer açar.

**Recordings tree view** — activity bar'da PlayForge ikonu altında.
`<workspace>/.playforge/sessions/*.json` listeler newest-first by mtime,

- Click: re-apply via Output Picker

- Context menu: Reveal in File Explorer

**Status bar** — `$(record) PlayForge [· <framework>]` idle,

**Bundled Chrome ext** — VSIX paketinde `chrome-ext/` mirror'ı taşınır

## 6. Edge case kontrol listesi

Aşağıdaki senaryolar release'in golden gate'i. Hepsi ✅ olmalı.

### 6.1. Workspace yok

VS Code'da hiçbir klasör açık değilken `PlayForge: Record` veya
`Apply Existing JSON`.

✅ **Beklenen**: Error message "PlayForge: open a folder before running
this command." Komut sessizce iptal olur.

### 6.2. Framework auto-detect başarısız

Boş bir klasör aç → `Apply Existing JSON…` → JSON seç → Output Picker'dan
ÖNCE QuickPick: "No framework detected — pick one for this run" → 4
seçenek.

✅ **Beklenen**: User seçim yapmadan `Esc` → komut iptal.

### 6.3. Chromium erken kapatma

Record akışı → Chromium aç → side panel'de Start basmadan veya kayıt
yapmadan **window'u X tuşuyla kapat**.

✅ **Beklenen**:

- VS Code notification: "Chromium was closed before Stop — no recording
  was captured."
- OutputChannel: `[playforge] Chromium was closed before Stop — no payload
to apply.`
- Hiçbir dosya yazılmaz, hang olmaz.

### 6.4. Boş kayıt (hiç step yok)

Record → side panel'de Start tıkla → hiç etkileşim yapma → Stop → VS
Code'a dön → Stop & Apply.

✅ **Beklenen**:

- Info message: "PlayForge: no steps recorded. Start a session in the
  side panel before stopping."
- Output Picker AÇILMAZ.
- Dosya yazılmaz.

### 6.5. Chrome ext bundle eksik

`vscode-extension/chrome-ext/` klasörünü sil → Record komutunu koş.

✅ **Beklenen**: Error message:

> Bundled Chrome extension missing at …\chrome-ext. Run `pnpm build &&
pnpm build:vscode` from the repo root so the Chrome extension is copied
> alongside the VS Code extension.

(Sonra `pnpm build && pnpm build:vscode` koş ve düzelt.)

### 6.6. Playwright Chromium binary yok

Yeni bir makinede `npx playwright install chromium`'u atlayıp Record koş.

✅ **Beklenen**: Playwright explicit hata mesajı:

> browserType.launchPersistentContext: Executable doesn't exist at
> ~/.cache/ms-playwright/chromium-…/chrome-win/chrome.exe

OutputChannel'da `[playforge] ERROR: …`, error message popup.

### 6.7. Mevcut dosya ile conflict

Workspace'te elle `pages/LoginPage.ts` oluştur (basit class içerikli):

```typescript
export class LoginPage {
  constructor(private page: any) {}

    console.log('old')
  }
}
```

Sonra Apply → Conflict picker.

- **Merge** → AST merger append eder; `existingMethod` korunur, yeni
  `login(email, password)` eklenir.
- **Diff** → diff editor `existingMethod` solda, yeni method'lar sağda.

### 6.8. CLAUDE.md marker block re-render

İki kez `Render Claude Prompt → claude-md mode` yap aynı slug'la.

✅ **Beklenen**: İkinci render `<!-- BEGIN playforge:login -->` …

eklemez.

### 6.9. Shadow DOM içeren flow

Custom element içeren bir sayfada kayıt yap (örn. `<lit-element>` form).

## 7. Bilinen kısıtlamalar (v0.7.0)

Bilinçli scope dışı bırakılanlar — issue açmaya gerek yok:

- **Hover provider** (test kodunda selector üzerine gelince scoring
  tooltip) — LSP-style indexing gerekir, Faz 8+.
- **Code lens** ("Last recorded X days ago") — file parsing infra, Faz 8+.
- **Inline diagnostics** (fragile selector uyarısı) — language service
  integration, Faz 8+.
- **Quick fix actions** (fallback'e replace) — language service, Faz 8+.
- **Auto-watch JSON folder daemon** — out of scope.
- **MCP server** — statik prompt dosyası seçildi, Claude Code slash command
  yeterli.
- **Marketplace publish** — VSIX yeterli, publisher account hazır olunca.
- **`.claude/agents/*.md`** sub-agent generator — yanlış granularity.
- **Bidirectional sync** (edited prompt → IR) — tek yönlü pipeline yeterli.
- **Multi-root workspace** (VS Code) — tek folder destekleniyor; multi-root
  ilk folder'ı kullanır.
- **Firefox / Edge** — Chrome only (Manifest V3 only).
- **Telemetry** — kalıcı olarak yok.
- **Bundled Chromium binary** in VSIX — kullanıcı `npx playwright install
chromium` koşmalı (~150 MB one-time).

| Hata / sembol                                      | Sebep                                                   | Çözüm                                                               |
| -------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
